# WPA2 Wireless Security & 4-Way Handshake Analysis

A practical guide and lab report on capturing, filtering, and analyzing the **WPA2 4-Way Handshake** process using **Wireshark**. This repository demonstrates how Wi-Fi devices perform mutual authentication and session key derivation over IEEE 802.11 networks using pre-captured PCAP files.

---

## 📌 Aim
To observe, filter, and analyze the WPA2 4-Way Handshake from a pre-captured network traffic file (`.pcap`/`.pcapng`) using Wireshark display filters to understand key exchange mechanisms in modern wireless security.

---

## 🧠 Theory Overview

WPA2-PSK (Wi-Fi Protected Access 2 - Pre-Shared Key) utilizes the **4-Way Handshake** to prove that both the client station (STA) and Access Point (AP) know the shared passphrase without ever sending the passphrase over the air.

### Key Derivation Terms
* **PMK (Pairwise Master Key):** Derived from the network SSID and pre-shared key (passphrase).
* **ANonce & SNonce:** Unique random values generated by the Authenticator (AP) and Supplicant (Station) respectively.
* **PTK (Pairwise Transient Key):** The session key used to encrypt unicast traffic. Derived from:  
  $$\text{PTK} = \text{PRF-512}(\text{PMK}, \text{"Pairwise key expansion"}, \text{MinMAC} \parallel \text{MaxMAC} \parallel \text{MinNonce} \parallel \text{MaxNonce})$$
* **GTK (Group Transient Key):** Key used to encrypt multicast and broadcast traffic.

### The 4-Way Handshake Exchange Sequence
```text
  Access Point (Authenticator)                         Client Station (Supplicant)
               |                                                   |
               | -------- 1. EAPOL-Key (ANonce) -----------------> |  (Client computes PTK)
               |                                                   |
 (AP computes  | <------- 2. EAPOL-Key (SNonce + MIC) ------------ |
     PTK)      |                                                   |
               | -------- 3. EAPOL-Key (GTK + ANonce + MIC) -----> |  (Client installs GTK)
               |                                                   |
               | <------- 4. EAPOL-Key (Confirmation / ACK) ------- |
               |                                                   |
               v         [ Encrypted Communication Begins ]        v
```

## 🛠️ Methodology & Procedure

### Prerequisites
* [Wireshark](https://www.wireshark.org/) installed.
* A capture file containing wireless traffic (`.pcap` or `.pcapng`).

### Steps
1. **Open the Capture File:** Launch Wireshark and navigate to `File` > `Open` to load your PCAP file.
2. **Apply Display Filter:** In the top filter bar, type the following display filter to isolate authentication frames:
   ```text
   eapol
   ```
   *(Optionally specify the AP's BSSID if multiple networks exist)*:
   ```text
   wlan.bssid == xx:xx:xx:xx:xx:xx && eapol
   ```
3. **Analyze Handshake Messages:** Select each frame and inspect the **Packet Details** pane under:
   `IEEE 802.11` $\rightarrow$ `802.1X Authentication / EAPOL Key Descriptor`

---

## 📊 Results

* **Traffic Isolation:** Display filters successfully isolated 4 sequential EAPOL-Key frames exchanged between the client and AP.
* **Key Parameter Verification:**
  * **Message 1:** Identified `ANonce` transmitted by the AP.
  * **Message 2:** Identified `SNonce` and `MIC` sent by the client.
  * **Message 3:** Confirmed distribution of the encrypted `GTK` along with `ANonce` and `MIC`.
  * **Message 4:** Confirmed final handshake ACK, enabling CCMP/AES encrypted data flow.

---

## 💬 Discussion

* **Security Strengths:**
  * Passwords are never sent directly over the air.
  * Perfect forward secrecy principles apply per session using randomized nonces (`ANonce` / `SNonce`), ensuring every connection generates a unique PTK.
* **Vulnerabilities:**
  * **Offline Dictionary Attacks:** Capturing all 4 handshake messages enables attackers to run offline dictionary/brute-force attacks against the PMK to reveal weak passphrases.
  * **WPA3 Mitigation:** Upgrading to WPA3 introduces **SAE (Simultaneous Authentication of Equals)**, preventing offline dictionary attacks even if handshakes are intercepted.

## 💡 Improvements & Advanced Techniques

* **Narrowed Filtering:** Combine MAC filters (`wlan.addr == <MAC>`) with protocol filters to remove capture noise in enterprise environments.
* **Decryption Testing in Wireshark:**
  1. Navigate to `Edit` $\rightarrow$ `Preferences` $\rightarrow$ `Protocols` $\rightarrow$ `IEEE 802.11`.
  2. Enable **Enable Decryption**.
  3. Add a new decryption key under **Decryption Keys** as `wpa-pwd` format (`password:SSID`).
  4. Verify that subsequent encrypted 802.11 data frames are converted into readable IPv4/IPv6 traffic post-handshake.
